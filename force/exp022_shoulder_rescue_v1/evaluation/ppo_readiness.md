# 持续球头任务接着做 PPO 前的接口检查

## 目前为什么不能直接续训

EXP-022 C 阶段策略用原始事件式球头训练：推速 0.20 m/s，接触力降至事件阈值并保持后，推手回撤。现有持续推压评估换成 `ForceRegulatedRail`，将 `force_done_ratio` 设为 0，让推手保持施力。原控制器的成功判据仍要求 `filtered_force < force_done`；此时右侧是 0，而滤波接触力非负，因此原 `event_success` 在持续协议下无法成立。253 号真值输入评估中该指标实际为 0。

原任务奖励 `force_unloading_task_reward` 用相邻两步的接触力下降量 `mapped_force_drop`，再与静止奖励混合。持续压力恒定时，该下降项回到中性值 0.5；它没有直接奖励持续 1 秒的低接触力和安全存活。直接拿原任务与原成功率指标续训，无法检验我们现在要的持续卸力目标。后一句是按当前奖励与成功判据代码做的推断，尚未用新 PPO 实验验证。

在标称 15 N 且遮蔽输入能安全持续加载的 269–271 号种子中，真值输入 3/3 失败；单独把真值力大小通道缩到 0、25%、50%、75% 也分别 3/3 失败。随后用独立的 277–284 号种子复核：遮蔽输入 8/8 安全持续加载，真值输入 8/8 失败，力大小清零但保留接触标志/几何输入仍 8/8 失败。这说明仅调整力标量不能让冻结 Actor 稳定。25 N 时完整肩部点+法向候选出现 4/4 关节硬限位，力、点、法向如何进入 Actor 也需要先确定。

Actor 检查点的观测归一化没有裁剪。原胸前短脉冲回合的作用点横向通道偏离训练均值中位数为 1.68 个标准差；25 N 肩部映射触发帧为 93.71 个标准差，法向横向为 40.76 个标准差。这是输入分布偏移的直接证据，尚不能据此给出某一通道单独造成硬限位的因果结论。

在 277–284 号种子追加的估计输入闭环中，V1 和肩部候选也都 8/8 失败。候选在自己轨迹上仍有 5/8 首次受力帧漏检、1/8 峰值漏检和 1/8 接触前误报。因此下一轮训练需要把真值策略稳定和估计器误检诊断分成两个验收门槛。

## 下一阶段最小可执行方案

1. 建一个独立的持续球头训练任务，复用已验证的物理导轨控制器参数和 5 ms 子步接触力采集；原 EXP-022 任务保持原样。训练与评估都记录实际力、接触几何、推手行程和失败类型。
2. 把成功条件定义为整回合无失败、躯干真实合力连续 ≥10 N 至少 1 秒、实际峰值在预定安全区间，并在相同种子的遮蔽对照下比较冲量与位移。把原事件式 `event_success` 留作原协议指标，不用于持续协议验收。
3. 为持续任务重写奖励：同时约束安全存活、关节/自碰撞、推手行程和真实力的时间积分或受力水平；防止策略只靠逃出推手行程、瞬时断触或接触力振荡获取奖励。奖励、阈值和验证种子在训练前固定。
4. 从 EXP-022 checkpoint 先用真值接触输入续训，验证真值策略在新种子上能稳定承受持续推压；之后才接估计力。先比较“只补三维力、策略接触映射仍固定胸前”与完整肩部映射，分别报告峰值漏检、首次接触、作用点、方向和失败类型。

本阶段的力估计候选保留为实验包，不改 `load_exp022_chest_estimator()` 的默认行为。
